## 当前目录结构
- 本目录下为解调信息波相关代码，是整个雷达站系统的一部分，
- 其中 src 文件夹下是gnuradio生成的解调代码，分为红方和蓝方两个阵容，其中每方包括一份解调信息波代码命名为BASE，两份解调干扰波代码命名为LEVEL1/2,分别对应解调一级干扰波和解调二级干扰波

## 通信
- 本机和工控机通过 IP 地址进行网络通信（TCP通讯）。
- 本机端（主控端）： server，默认监听地址为0.0.0.0, 监听端口为9999
- 工控机端（执行端）： client, Pluto SDR 设备 URI为192.168.2.1", 监听ip为192.168.1.10

## 架构与交互定义
### 角色定义：
- 本机（主控端）： 运行主线程 main_event_loop.py，调用并初始化`recriver.py`中的 `解调控制器DemodController`，
- 工控机（执行端）： 存放 src 目录代码，运行 `解调进程管理器DemodProcessManager`

### 初始化阶段
雷达站系统开启后，本机会启动主线程 main_event_loop.py， 在这里面需要根据阵容初始化`解调控制器`, 工控机会启动解调线程，并初始化`解调进程管理器`来建立连接，本机下发当前阵容(红\蓝)，完成`解调进程管理器`的初始化，如果为红方，`解调进程管理器`则使用红方代码，否则使用蓝方代码。

### 干扰解调循环
1. `解调进程管理器`初始化完成后，即自动开启解调信息波进程，`解调控制器`根据事先设置的目标解调等级`target_level`(通过配置文件params.yaml事前传递给雷达站主线程)，调用`try_decode`函数请求`解调进程管理器`解调干扰波，具体见下一节`解调干扰波`
2. `解调控制器`内部需要维护一个`当前干扰波等级current_level`，`当前干扰波等级`默认初始为1（代表当前面临1级干扰，需调用 LEVEL1 代码）。解调 LEVEL1 成功后，等级升为2（代表面临2级干扰，需调用 LEVEL2 代码）。解调 LEVEL2 成功后，等级升为3（代表最高等级，干扰已全部解调，只需维持 BASE 进程正常运转）。
3. `解调控制器`请求解调干扰波后，`解调进程管理器`内部启动解调对应等级的解调干扰波线程，解调不一定成功，若`解调控制器`发现超时后(timeout=30)，说明解调失败，关闭此次请求，并且`当前干扰波等级`保持不变
4. `解调控制器`向工控机发起解调请求后，开启一个 30s 的超时倒计时（异步），若 30s 内收到‘解调成功’的回执，则更新当前等级并进入下一阶段；若 30s 倒计时结束仍未收到成功信号（即超时），则视为本次解调失败，当前等级不变，并立即重新发起当前等级的解调请求，以此循环，直到达到设定的 `target_level`。
